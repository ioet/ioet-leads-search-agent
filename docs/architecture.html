Leads Search Agent — Architecture

Current implementation: parent + child WfSpecs, thin workers → HTTP microservices, direct synchronous writes to HubSpot and Slack (no SQS). Open in a browser to render diagrams.

1. Combined workflow (parent + child)

flowchart TD
  S1["search-companies"] --> S2["count-companies (local)"]
  S2 --> C0{"count = 0?"}

  C0 -->|"yes"| E1["build-empty-search-notification (local)"]
  E1 --> N["notify → POST /v1/notify"]

  C0 -->|"no"| S3["score-companies-icp"]
  S3 --> S4["select-top-leads (local)"]
  S4 --> S4b["fetch-ioet-skills-catalog (local)"]
  S4b --> S5["spawn child per lead"]

  S5 --> C1

  subgraph child ["enrich-and-publish-lead (×N)"]
    direction LR
    C1["find-decision-makers"] --> C2["sanitize-public-fields"]
    C2 --> C2b["extract-job-skills"]
    C2b --> C3["match-ioet-skills"]
    C3 --> C3b["draft-outreach-email"]
    C3b --> C4["upsert-hubspot"]
    C4 --> C5["complete(lead)"]
  end

  C5 --> S6["build-campaign-summary (local)"]
  S6 --> N

  N --> Done(["complete / Done"])

(local) tasks run in the worker process. Both branches converge on a single notify task → Slack. upsert-hubspot writes to HubSpot directly; dry_run skips HubSpot writes.

4. Request flow

sequenceDiagram
  participant T as Trigger
  participant LH as LH Kernel
  participant W as Worker
  participant Svc as Microservice
  participant Ext as External API

  T->>LH: start leads-search-workflow
  LH->>W: search-companies
  W->>Svc: apollo
  Svc->>Ext: Apollo.io
  LH->>W: count-companies
  alt count = 0
    LH->>W: build-empty-search-notification
    LH->>W: notify
    W->>Svc: notify /v1/notify
    Svc->>Ext: Slack
  else count > 0
    LH->>W: score → select
    loop each company
      LH->>LH: enrich-and-publish-lead
      LH->>W: upsert-hubspot
      W->>Svc: hubspot /v1/upsert-lead
      Svc->>Ext: HubSpot CRM
    end
    LH->>W: build-campaign-summary → notify
    W->>Svc: notify /v1/notify
    Svc->>Ext: Slack
  end
